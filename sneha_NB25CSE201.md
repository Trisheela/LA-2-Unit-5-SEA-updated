A group of developers is working on an open-source Library Management System hosted on GitHub. A student identifies that the project lacks proper documentation explaining how users can issue and return books.
Demonstrate how the student can contribute to the open-source project by improving its documentation. Explain the GitHub workflow involved, from forking the repository to submitting a Pull Request.
Expected contribution:
●	Introduction to open-source software engineering
●	Importance of contributing to open-source projects
●	Steps to fork a repository
●	Creating or modifying a documentation file
●	Committing changes and submitting a Pull Request
●	Benefits of collaborative software development
●	GitHub contribution workflow diagram
1. Introduction to Open-Source Software Engineering
Open-source software is software whose source code is publicly available. Anyone can view, use, modify, and contribute to it.

GitHub is a platform used by developers to store, manage, and collaborate on open-source projects.

Example: A Library Management System hosted on GitHub allows developers and students to improve its code and documentation.
2. Importance of Contributing to Open-Source Projects
1. Improves programming and technical skills.
2. Provides real-world project experience.
3. Helps developers learn teamwork.
4. Improves software quality and documentation.
5. Builds a strong GitHub profile for career opportunities.
3. Steps to Fork a Repository
1. Open the Library Management System repository on GitHub.
2. Log in to your GitHub account.
3. Click the Fork button.
4. Select your GitHub account.
5. A copy of the original repository will be created in your account.
4. Creating or Modifying a Documentation File
1. Open the forked repository.
2. Find the README.md file.
3. Click the Edit button.
4. Add documentation explaining how to issue and return books.
How to Issue a Book:
- Log in to the Library Management System.
- Search for the required book.
- Select the book and click Issue.
- Confirm the issue request.
How to Return a Book:
- Log in to your account.
- Open the Issued Books section.
- Select the book.
- Click Return Book and confirm.
5. Save the changes.
5. Committing Changes and Submitting a Pull Request
1. Click Commit Changes.
2. Enter a meaningful commit message, such as "Added book issue and return documentation".
3. Save the changes to your forked repository.
4. Click Contribute and select Open Pull Request.
5. Add a title and description explaining your changes.
6. Click Create Pull Request.
7. The project maintainers review your contribution.
8. If approved, they merge the changes into the original repository.
6. Benefits of Collaborative Software Development
1. Developers can share knowledge and ideas.
2. Errors can be identified and corrected easily.
3. Software quality improves.
4. Work can be completed faster.
5. Students gain practical development experience.
